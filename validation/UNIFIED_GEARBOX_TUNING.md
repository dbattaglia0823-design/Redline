# Unified transmission tuning

Tuning & Test Track → Tune → Gearbox now contains one vertically scrolling native control list. The order is Number of Gears, Final Drive Ratio, then 1st through the last equipped gear. Gear-selection arrows and settings pagination are removed from this group. Existing boost-by-gear selection in Power is unchanged. Shift RPM, firmness and launch gear controls follow the complete ratio list where applicable.

Every row has a minus button, horizontal slider, plus button, and numeric value. Buttons adjust ratios/final drive by 0.01; three decimals preserve visibility of factory ratios such as 4.696. Gear count uses integer steps. Speeds alongside ratios update directly from the current final drive, tire radius and RPM limit, in the player's selected units. These are theoretical speeds at the RPM limit, not drag-limited top speed or quarter-mile predictions.

## Shared gearing rules

The page uses the latest main branch’s tuning access rules: gearing is adjustable for the current transmission without a cassette/final-drive-kit purchase. Active races block tuning. Existing transmission conversions and saved transmission tunes are preserved.

| Transmission architecture | Available gears |
| --- | --- |
| Manual | 3–6 |
| Sequential / Paddle / DCT | 5–7, expanded to include the factory count (for example an 8-speed OEM DCT) |
| Conventional automatic | 3–10 |
| Drag automatic | 2–4 |

OEM outliers expand the architecture's range to include the factory count. Catalog and OEM transmissions use the same limits. Final drive supports continuous 2.00–5.50 adjustment; gear ratios support 0.30–6.00, with at least 0.03 and 2.5% spacing between adjacent gears. Shared validation prevents crossed or nonfinite ratios. Untouched close factory pairs remain valid when editing another gear, preserving the authored R8 gearing; edits to that pair use the normal spacing limits. The 0.30 floor also preserves the factory Z06 overdrive ratios. This retains current main’s transmission families and final-drive limits while replacing separate per-gear navigation and paging with direct controls.

Growing the count retains existing ratios and generates descending overdrives. If a tightly packed low end cannot fit the additional gears above 0.30, the minimum required adjustments preserve valid spacing. Reducing the count retains the remaining prefix. Shift RPM and boost arrays resize while preserving existing entries; newly needed entries inherit the previous setting. Gear-dependent launch settings are clamped when gears are removed.

## Physics, saving and input

The UI calls `DriverProfile.tune_hardware`; the solver reads the resulting gearing through `TransmissionCatalog` validation. No parallel tune model or new save file is used. Live drag changes update actual ratios and final drive immediately. The expensive shift-plan search and disk save run on release; keyboard/button edits commit immediately. Finishing or leaving an edit flushes pending changes. Live redline-speed labels remain immediate during dragging.

Current tuning is saved per vehicle. Gearing is also remembered per owned transmission when switching gearboxes. The existing `transmission_tunes` and `transmission_parts` history is reused when swapping gearboxes; no additional save bank is introduced. Named presets retain dynamic counts and ratios and validate gear count before dependent arrays. Older saves without gear-count data continue using the factory count.

Native controls handle mouse clicks, drag, wheel scrolling, focus and keyboard adjustment. A touch adapter distinguishes horizontal slider edits from vertical list swipes and button taps; release/cancel finalizes pending changes. Touch scrolling has a decaying inertial glide, disabled by Reduced Motion. Mobile targets grow independently for portrait and compact landscape. Input is routed to this panel before the custom menu hit map to avoid duplicate activation. Explicit content-coordinate focus scrolling keeps the complete focused row visible. Screenshot review caught incorrect automatic focus scrolling; the test now asserts the final gear slider is actually visible, rather than only programmatically adjustable.

```sh
godot --headless --path . --editor --quit
XDG_DATA_HOME=/tmp/redline-gearing-model godot --headless --path . --script tests/test_unified_gearing.gd
XDG_DATA_HOME=/tmp/redline-gearing-ui godot --path . --audio-driver Dummy --script tests/test_unified_gearing_ui.gd
```

No environment configuration or publication was changed.
